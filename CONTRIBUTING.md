# Contribuir

Se aceptan reportes de errores, pruebas y mejoras que mantengan el enfoque **DFIR defensivo**.

1. Trabaja en una rama dedicada y describe claramente el cambio.
2. Ejecuta `python3 -m unittest discover -s tests -v`.
3. Incluye pruebas de regresión para cada corrección.
4. Usa únicamente **datos sintéticos** en ejemplos, commits, issues y pull requests.
5. No incluyas registros de clientes, tokens, nombres, correos, IP públicas reales ni artefactos originales.
6. Las nuevas detecciones deben indicar evidencia mínima, posibles falsos positivos y limitaciones.

Para una vulnerabilidad de seguridad, sigue [SECURITY.md](SECURITY.md) y evita abrir un issue público con detalles de explotación.
